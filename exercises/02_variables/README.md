# 02 資料項目與 MOVE ★

主題：`MOVE`、`PIC X`、`PIC 9`、`PIC 9(3)V99`

## 學習目標

完成這一題後，你會：

- 分辨三種最常用的 PICTURE：文字 `PIC X(n)`、整數 `PIC 9(n)`、含小數 `PIC 9(n)V99`。
- 知道 `V` 是「隱含小數點」：它標出小數點的位置，但本身不佔位置。
- 正確使用 `MOVE 來源 TO 接收端`，不把方向寫反。

## 這題要做什麼

要修改的檔案：`Variables.cbl`（不要改 `VariablesTest.cbl`）

| 段落 | 完成後應該達成 |
| --- | --- |
| `FILL-FIELDS` | `WS-NAME` 是 `Amy`、`WS-COUNT` 是 45、`WS-PRICE` 是 **12.50** 元 |
| `COPY-FIELDS` | 三個 `-OUT` 欄位分別拿到 `Amy`、45、12.50，而且 `WS-COUNT` 本身不能被清掉 |
| `SHOW-FIELDS` | 已經寫好，不用改 |

這題還會比對 `DISPLAY` 的輸出（見 `expected.txt`）：

```text
NAME: Amy
COUNT: 45
PRICE: 12.50
```

規則：段落名稱不要改。

## 觀念講解

### 1. PICTURE 決定欄位能裝什麼

| 寫法 | 意思 | 例子 |
| --- | --- | --- |
| `PIC X(6)` | 6 個任意字元 | `"Tom   "` |
| `PIC 9(4)` | 4 位數整數（不含正負號） | `0042` |
| `PIC 9(4)V99` | 4 位整數 + 2 位小數 | `0042.75` |

`V` 是**隱含小數點**：電腦知道小數點在哪裡，但它不會變成一個字元存在欄位裡。

### 2. 數字放進含 `V` 的欄位

數字常數裡的小數點會對齊到 `V` 的位置：

```cobol
01  WS-WEIGHT   PIC 9(3)V99.

MOVE 3.2  TO WS-WEIGHT     *> 3.20
MOVE 320  TO WS-WEIGHT     *> 320.00（不是 3.20！）
```

也就是說，`320` 會被當成「三百二十」，不會自動幫你「除以 100」。

（`DISPLAY` 數字欄位時，這個系統不會印出前導零，所以 `3.20` 不會顯示成 `003.20`。）

### 3. `MOVE` 的方向

```cobol
MOVE WS-A TO WS-B          *> 把 WS-A 的值複製到 WS-B，WS-A 不變
```

- 讀法就像英文的「把 A **搬到** B」：左邊是來源，`TO` 右邊是接收端。
- 接收端原本的值會被**覆蓋**；來源不會被改動。
- 寫反了不會有任何錯誤訊息，只是值被搬到相反的方向。

## 常見錯誤

- **金額差了 100 倍**：把「分」當成「元」寫進 `9(n)V99` 欄位。先想清楚數字的單位，再決定常數怎麼寫。
- **`MOVE` 方向寫反**：來源被接收端（通常是 0 或空白）蓋掉，結果兩邊都錯。
- **以為文字欄位會「剛好」**：`PIC X(10)` 放 `Amy` 其實是 `Amy` 加 7 個空白。斷言比較時會補空白再比，所以不影響這題，但接字串時要特別注意。
- **段落之間的順序**：檢查器會先 `PERFORM FILL-FIELDS` 再 `PERFORM COPY-FIELDS`，`COPY-FIELDS` 依賴前一段放好的值。

## 操作步驟

1. 在專案根目錄執行 `.\coblings.cmd run 02_variables`（Linux／macOS：`./coblings.sh run 02_variables`），開始監看這一題。
2. 用編輯器打開本資料夾的 `Variables.cbl`，照「這題要做什麼」修改。**不要改 `VariablesTest.cbl`**，它是這一題的驗收標準。
3. 存檔後系統會自動檢查：
   - **解析錯誤**：訊息裡有檔名和行號，照著修正語法。
   - **期望／實際不符**：看斷言的標籤，找出是哪個段落的結果不對。
   - **全部通過**：自動跳到下一題。
4. 卡關時執行 `.\coblings.cmd hint 02_variables` 看提示。
5. 改亂了想重來，執行 `.\coblings.cmd reset 02_variables` 還原成原題（你改過的版本會備份到 `.coblings/backup/`）。
